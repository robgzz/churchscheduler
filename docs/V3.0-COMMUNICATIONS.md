# V3.0 Communications

V3.0 keeps Azure Communication Services isolated from scheduling logic in `src/communications/`.

- Authentication: the existing Container Apps user-assigned managed identity. No ACS key or connection string is sent to the browser.

## Delivery rules

- Published announcements: active members with a phone receive SMS and active members with an email receive email. Only the announcement text and optional activity address are sent; attachments remain in the app.
- Worship assignments: email/SMS are queued 30 minutes after the assignment becomes visible in the app, then again three days and one day before the service.
- Reassignments reset the assignment notification anchor so the newly assigned member gets the same notification pattern.
- New petitions and visitor forms: active administrators with a phone number receive an SMS alert.
- All ACS attempts, successes and failures are written to `NotificationLogs`.
- `NotificationQueue` uses deterministic IDs so a scheduled job can run repeatedly without duplicating the same notification. Failed items retry up to three times.

## Church Administrator testing

Admin > Settings > Advanced > Communications lets the Church Administrator choose a member and send either a test email or SMS. The browser receives only configuration status, sender address/number, and results; ACS credentials remain server-side.

## Scheduling cadence

The GitHub deployment workflow updates the Container Apps scheduler job to `*/5 * * * *` so communication due times are normally processed within five minutes of their target time. Container Apps cron schedules are evaluated in UTC; church-day calculations are done in the configured church timezone.

## SMS consent

The software supports explicit notification opt-out with `notificationPreferences.sms=false` or `notificationPreferences.email=false`. The church is responsible for collecting and retaining the carrier-required SMS consent/opt-in before storing a mobile number for automated SMS use and for honoring carrier opt-out requirements.
