# Upgrade Westbury Church Hub V4.1.0 -> V4.2.0

V4.2.0 uses the same Azure resource topology introduced by V4.1.0. No additional tables, secrets, or Container Apps are required for this release.

## Recommended production upgrade

1. Back up or export the current member list.
2. Replace/update the repository with the V4.2.0 source.
3. Review and commit the change to `main`.
4. Push to GitHub. The included GitHub Actions workflow runs syntax/tests, builds the image, deploys the Container App and scheduler job, and verifies health.
5. Verify `/healthz` reports version `4.2.0`.
6. In Admin > Manage Modules, confirm Chat Hub and Follow-up are enabled only if the church wants them visible.
7. Test RSVP with a normal member account and verify the name appears in the admin RSVP view/report.
8. Test one Chat Hub read query and one authorized admin workflow.

## Exact-state member workbook

The package includes:

`imports/Westbury-Members-Updated-From-Handwritten-Lists.xlsx`

The workbook uses `AssignmentEligibilityMode=explicit`. In V4.2 this tells the importer to replace Ministries, Services and AssignmentEligibility with the values in the workbook, including intentionally blank values. This prevents obsolete eligibility from surviving an import.

Before importing production data, use the admin import preview/review, then perform the import and export the member list again to verify the desired result.

## Infrastructure script

The V4.2 package still includes the full `infra/` and `scripts/first-deploy.ps1` assets for disaster recovery or infrastructure reconciliation. A normal V4.1 -> V4.2 application upgrade does not require running first-deploy again because V4.2 does not add Azure resources.
