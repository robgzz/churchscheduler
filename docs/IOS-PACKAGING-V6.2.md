# iOS packaging readiness — V6.2.0

V6.2.0 contains the application-side changes needed to continue packaging Westbury Church Hub for iOS without changing the existing Azure web deployment model.

## What V6.2 already provides

- Capacitor iOS package declared at the same 8.5.1 family as the existing Capacitor runtime.
- Bundle ID remains `com.exonuvia.westburychurchscheduler`.
- App display name is `Westbury Church Hub`.
- Native push registration now reports the real platform (`android` or `ios`) instead of hard-coding Android.
- `PushDevices` accepts both Android FCM and iOS APNs device tokens.
- The notification service routes Android devices to FCM and iOS devices to APNs.
- APNs token authentication is supported through `APNS_TEAM_ID`, `APNS_KEY_ID`, `APNS_BUNDLE_ID`, and a private `.p8` key stored as an Azure Container Apps secret.
- APNs production is tried first; if a newly registered development token returns a token-environment mismatch, the backend retries against the sandbox environment and records the working environment.
- Notification taps continue to use the existing route metadata (`schedule`, `church`, `petitions`, etc.).

## Important production choice

V6.2 intentionally keeps the existing Capacitor `server.url` pointed at the production Azure Container App. This preserves the current cookie/session and same-origin security model while the native shell is introduced. Do not remove `server.url` immediately unless the app is also migrated to a native-token or fully tested cross-origin authentication model. The native iOS project can still be created, signed, and tested with this configuration.

## On the Mac

After cloning the V6.2 repository:

```bash
npm install
npm run ios:add
npm run ios:sync
npm run ios:open
```

If `ios/` already exists, skip `npm run ios:add` and run only sync/open.

In Xcode:

1. Select the App target.
2. Choose the correct Apple Developer Team.
3. Confirm bundle ID `com.exonuvia.westburychurchscheduler`.
4. Enable **Automatically manage signing**.
5. Add the **Push Notifications** capability.
6. In `AppDelegate.swift`, add the Capacitor APNs registration callbacks described by the Capacitor Push Notifications plugin if they are not already generated by the installed template.
7. Install on a physical iPhone and allow notifications.

## Configure APNs on Azure

After creating an APNs key in the Apple Developer portal, run from PowerShell:

```powershell
.\scripts\configure-apns-push.ps1 `
  -AuthKeyP8 "C:\path\AuthKey_XXXXXXXXXX.p8" `
  -TeamId "YOUR_TEAM_ID" `
  -KeyId "YOUR_KEY_ID"
```

This configures both `westburyapp-web` and `westburyapp-scheduler` without placing the private key in the repository.

## End-to-end test

1. Install the iOS build on a physical iPhone.
2. Sign in to Church Hub.
3. Allow notifications.
4. Confirm a row is created in `PushDevices` with `platform=ios`.
5. From Admin > Settings > Communications, send a Push test to that member.
6. Test foreground, background, locked phone, and notification-tap routing.
7. Repeat from TestFlight before App Store submission.

## Security note

Never commit the APNs `.p8` key. V6.2 sends only the APNs device token to the backend; the signing key stays server-side in Azure Container Apps secrets.
