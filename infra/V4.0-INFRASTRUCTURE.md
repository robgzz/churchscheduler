# Westbury Church Hub V4.0 infrastructure

This infrastructure remains managed through GitHub. The Bicep deployment provisions the external Azure Container App, scheduled Container Apps Job, Azure Container Registry, Blob/Table Storage, managed identity, and required RBAC in commercial Azure.

V4 changes the scheduled job default from every five minutes to every minute. No new Azure service is required for Events, Follow-up, module settings, or the new Children Care state fields; the application creates the additive Azure Tables on startup.

## Existing deployment

For a normal application upgrade, use the full source ZIP and push its contents to the existing GitHub repository. The workflow updates the Container App and scheduled job. Do not redeploy Bicep unless you intentionally want infrastructure reconciliation.

## First deployment or reconciliation

PowerShell:

```powershell
.\scripts\first-deploy.ps1 -ResourceGroup "rg-church-scheduler-v2" -Location "centralus"
```

Then run `configure-github-oidc.ps1`, add the printed GitHub secrets, and push the full source repository to `main`.

## Required GitHub secrets

- `AZURE_CLIENT_ID`
- `AZURE_TENANT_ID`
- `AZURE_SUBSCRIPTION_ID`
- `AZURE_RESOURCE_GROUP`
- `AZURE_ACR_NAME`
- `AZURE_CONTAINER_APP_NAME`
- `AZURE_CONTAINER_JOB_NAME`

The workflow uses OIDC and does not store an Azure password. Keep the infrastructure-only archive outside the Git repository unless it is being used to restore the repository's matching infrastructure files.
